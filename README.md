# F&G 알림봇

CNN Fear & Greed Index와 주요 시장 시세를 수집하고, 공포·완충 요인을 짧은 한국어 설명과 함께 전달하는 개인용 알림 도구입니다.

설명할 요인은 Python 규칙이 먼저 선정합니다. LLM에는 선택된 지표만 전달하고, 뉴스·시장 원인·가격 전망을 임의로 추가하지 않도록 요청합니다.

> Python이 무엇을 설명할지 결정하고, LLM은 선택된 정보를 읽기 쉬운 문장으로 바꿉니다.

## 출력 예시

아래는 보고서 구성을 보여주는 **설명용 예시**입니다. 실제 수신 화면이나 현재 시장 분석이 아니며, AI 해석 문구는 생략했습니다.

```text
🌅 아침 시장 브리핑
주요 시장지표: 환율·비트코인·코스피·나스닥·S&P500·선물

📊 F&G 시장심리
종합: [점수와 등급] / 기준 시각: [데이터 갱신 시각]
주요 공포 요인: [Python이 선정한 최대 2개 지표와 점수]
완충 요인: [Python이 선정한 1개 지표와 점수 또는 없음]
한 줄 해석: [Python 규칙 요약]
           [응답 검사를 통과했을 때만 추가하는 AI 설명]
데이터: CNN Fear & Greed / 요약: Python 규칙 / 설명: AI 보조
```

시장시세 일부를 수집하지 못하면 누락 항목을 표시합니다. 모델 호출이나 응답 검사가 실패하면 AI 설명 없이 기본 보고서를 제공합니다.

## 프로젝트 배경

제가 사용하던 [기존 봇](https://github.com/0gnm0-afk/fng-chatbot)은 F&G 종합점수와 환율·비트코인·주가지수·선물 시세를 Telegram으로 전달했습니다. 하지만 종합점수만으로는 일곱 구성 지표 중 무엇이 공포 쪽에 있고 어떤 지표가 다른 모습을 보이는지 빠르게 파악하기 어려웠습니다.

구성 지표의 의미를 함께 읽고 싶어 LLM 설명을 추가했습니다. 이때 모델이 제공되지 않은 뉴스나 그럴듯한 시장 원인을 만들어내지 않도록, **설명할 근거를 Python으로 먼저 정하고 모델의 역할을 제한**했습니다.

## 설계와 역할 분담

| 구성요소 | 맡긴 역할 | 맡기지 않은 일 |
|---|---|---|
| Python | 조회·입력 검증·요인 선정·기본 요약·응답 검사 | 자유로운 시장 원인 추론 |
| LLM | 선택된 지표의 의미를 짧은 한국어로 설명 | 요인 선정·뉴스 조사·가격 예측 |
| 사용자 | 보고서 확인·투자 활용 판단·발송 제어 | 시스템에 매매 결정 위임 |
| 전달 기능 | 미리보기·Telegram 발송 | 자동 주문 |

기본 보고서는 Python만으로 생성합니다. LLM은 필수 처리 단계가 아닌 보조 설명이며, API에 문제가 생겨도 기본 기능을 유지하도록 했습니다.

## 작동 흐름

```text
CNN 구성 지표 수집·검증 → Python 요인 선정 → 선택된 정보만 NVIDIA API에 전달
→ LLM 설명 생성 → Python 응답 검사 → 기본 요약 + AI 설명 → 미리보기 또는 발송
```

- **공포 요인:** 공포·극단적 공포 등급에서 점수가 낮은 최대 2개.
- **완충 요인:** 중립·탐욕·극단적 탐욕 등급에서 점수가 가장 높은 1개.
- 조건에 맞는 지표가 없으면 없다고 표시하며, 동점은 고정 순서로 처리합니다.

공포·완충은 보고서 생성을 위한 분류이며, 시장 움직임의 실제 원인을 입증한 것은 아닙니다.

모델에는 선정한 지표의 이름·점수·등급·설명 기준만 보냅니다. 예를 들어 변동성 지표에는 “VIX와 50일 이동평균 비교”라는 기준이 포함됩니다. 선정·검사 코드 예시는 [설계 노트](docs/design-notes.md)에 보존했습니다.

모델 입력을 만드는 실제 코드는 다음과 같습니다. `context.factors`에는 Python이 이미 선정한 요인만 담깁니다.

```python
user_payload = {
    "selected_factors": [factor.to_dict() for factor in context.factors],
}
```

각 요인은 역할·지표 ID·이름·점수·등급·설명 기준을 포함합니다. 모델이 요인을 다시 선정하도록 요청하지 않고, 입력 요인의 의미만 설명하도록 지시합니다. 이 분리는 같은 입력에서 선정 결과를 재현하면서 설명 생성만 모델에 맡기기 위한 선택입니다.

## 검증과 실패 처리

LLM 응답을 그대로 사용하지 않고 다음을 검사합니다.

- 지정된 JSON 구조와 필수 필드
- 설명 전체가 1~2줄·300자 이내인지
- 참조 지표 ID와 순서가 Python 선정 목록과 정확히 일치하는지

API 호출이나 검사가 실패하면 AI 설명을 제외하고 Python 규칙 보고서만 유지합니다. 테스트에는 선택한 요인만 모델 입력에 들어가는지와 잘못된 형식·길이·참조 목록을 거부하는지 확인하는 항목이 있습니다.

이 검사는 **출력 형식과 참조 목록을 통제하지만 문장의 사실성은 보장하지 않습니다.** 선택하지 않은 지표가 본문에 등장하거나 입력에 없는 원인을 덧붙이는 경우까지 의미 수준에서 모두 판별하지는 못합니다. 환각을 제거했다기보다 근거 없는 설명이 개입할 여지를 줄이고, 실패 시 기본 기능을 유지하기 위한 설계입니다.

## 구현된 변화

| 기존 공개 봇 | 현재 공개 코드 |
|---|---|
| F&G 종합점수와 주요 시세 전달 | 구성 지표와 선정 요인까지 표시 |
| 숫자의 의미는 사용자가 해석 | 선택된 요인의 의미를 짧게 설명 |
| 정해진 알림 문구 | 규칙 요약과 AI 보조 설명 분리 |
| Flask 발송 경로 | 로컬 MCP 조회·미리보기·발송 |
| LLM 미사용 | LLM 실패 시 규칙 보고서 유지 |

이는 구현된 기능의 변화입니다. 이해도·시간 절감·환각 감소율·투자성과 개선은 아직 측정하지 않았습니다.

## 한계와 다음 검증

실사용 중 비슷한 요인이 반복해서 선정되면, 해석도 점수와 등급을 풀어 쓴 뻔한 문장으로 반복되는 문제가 있었습니다. 환각을 줄이려고 입력을 좁혔지만, 모델이 더해줄 수 있는 맥락과 해석의 폭도 제한됐습니다. Python 요약보다 LLM 설명이 얼마나 더 유용한지 다시 확인할 필요가 있습니다.

다음에는 실제 출력 표본으로 아래 항목을 평가하려 합니다.

- 선정 지표와 설명이 일치하고, 입력에 없는 시장 원인을 추가하지 않는가?
- 가능성을 사실처럼 단정하거나, 동일 입력에서 설명이 과도하게 달라지지 않는가?
- Python 요약만 있을 때보다 이해에 도움이 되는가?
- 공포 요인 2개·완충 요인 1개라는 규칙이 유용한가?

표현만 다양하게 바꾸기보다 검증 가능한 변화 정보가 필요한지, 규칙 설명만으로 충분한지 비교할 계획입니다. 웹 데이터의 변경·누락과 모델 API의 오류·이용 제한에도 영향을 받습니다.

## 실행과 발송 제어

현재 공개본은 **로컬 MCP 서버**입니다. 기존 Google Cloud 예약 봇과 같은 배포 구성이 아니며, 모델 추론만 NVIDIA API에 요청합니다. CNN·네이버·Yahoo의 웹 JSON을 조회하고, `httpx`·FastMCP·Telegram Bot API를 사용합니다. 현재 지정 모델은 `deepseek-ai/deepseek-v4-flash`입니다.

Windows PowerShell에서 저장소 루트 기준으로 실행합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
```

`.env.example`은 예시이며 자동으로 읽히지 않습니다. `NVIDIA_API_KEY`와 발송용 `TELEGRAM_BOT_TOKEN`·`TELEGRAM_CHAT_ID`는 사용자 환경변수에 설정합니다. 실제 값을 저장소에 기록하지 않습니다.

| 환경변수 | 용도와 기본 동작 |
|---|---|
| `NVIDIA_API_KEY` | NVIDIA 모델 호출. 없으면 규칙 보고서 유지 |
| `TELEGRAM_BOT_TOKEN` | Telegram 봇 인증. 없으면 발송 불가 |
| `TELEGRAM_CHAT_ID` | 수신 대상. 없으면 발송 불가 |
| `MCP_ALLOW_TELEGRAM_SEND` | 기본 `true`. `false`면 발송 차단 |
| `CNN_FNG_CACHE_TTL_SECONDS` | CNN 메모리 캐시 유효시간. 기본 300초 |

| 도구 | 동작 |
|---|---|
| `get_fear_greed_report` | 규칙 보고서 조회. 모델 호출·발송 없음 |
| `preview_telegram_report` | AI 설명을 포함할 수 있는 미리보기. 발송 없음 |
| `send_telegram_report` | 메시지 생성 후 Telegram 발송 |

**현재 포함된 Skill은 기본적으로 발송하며, 매번 별도 승인을 묻지 않습니다.** 확인만 하려면 “미리보기만, 전송하지 마”라고 요청하거나 `MCP_ALLOW_TELEGRAM_SEND=false`로 설정한 뒤 앱을 다시 시작하세요. 내부 해시는 전송 원문의 일치를 확인하며 사용자 승인을 뜻하지 않습니다.

대화형 실행을 “미리보기 기본 → 명시적 전송 요청”으로 바꾸는 것은 후속 개선 과제입니다. 예약 자동발송을 연결한다면 사전에 정한 범위와 구분해야 합니다. 이번 문서 개정에서는 실행 동작을 변경하지 않았습니다.

연결 설정·환경변수·직접 실행 방법은 [설계 노트의 설치 안내](docs/design-notes.md#설치)를 참고하세요.

```powershell
python -m pytest -q
python -m ruff check .
python -m ruff format --check .
```
